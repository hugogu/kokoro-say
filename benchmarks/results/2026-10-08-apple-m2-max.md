# 2026-10-08, MacBook Pro with Apple M2 Max

This report replaces the earlier ones of the day (the git history has them). They measured only
`say -v Samantha` and called it plain `say`, which speaks with a different and much heavier voice
on this Mac, and they ran on a Python build that starts slowly (see "The Python build" below).
This one measures both `say` voices, on the Python that `uv tool install` gives.

The machine was in ordinary desktop use during the run: the one-minute load average was 5.4 at the
start and 7.6 after the timings and the transcription, on 12 cores. `ksay` is the only engine that
spreads over many cores (the default voice's helper peaked at one), so its times are, if anything,
pessimistic.

## Speed and memory

Wall time of one command from launch until its file is written, median of six runs (three for the
long text) after a warm-up run. Memory is the command's peak resident set size. For `say` that is
the `say` process only. The default voice is produced in a `SiriAUSP` helper that was not running
before. Sampling `ps` while `say` spoke the long text, twice and outside the script, the helper's
resident memory peaked at 174 MB and 172 MB and its CPU use at 104%, about one core. With Samantha
no such helper appears and the speech services were each under 20 MB.

| Engine | short (6 words) | medium (63 words) | long (268 words) | speed on long text | peak memory |
| --- | ---: | ---: | ---: | ---: | ---: |
| ksay | 1.03 s | 3.93 s | 14.60 s | 6× real time | 1005 MB |
| say (default voice) | 1.28 s | 3.69 s | 11.78 s | 7× real time | 37 MB |
| say (Samantha) | 0.81 s | 0.94 s | 1.26 s | 68× real time | 36 MB |
| eSpeak NG | 0.15 s | 0.16 s | 0.22 s | 393× real time | 65 MB |

The three texts come to about 2, 22 and 91 seconds of speech with `ksay`.
`ksay` uses 0.6 GB for the short text and 1.0 GB for the long one.

## Intelligibility

Whisper transcribes the recording; word error rate is computed after both texts go through Whisper's
English text normalizer. For the numbers set, formatting between digits is ignored too, so `415-555-0132`
matches `415 555 0132`.

| Engine | plain speech: word error rate | plain: sentences heard perfectly | numbers and names: word error rate | numbers: sentences heard perfectly |
| --- | ---: | ---: | ---: | ---: |
| ksay | 0.6% | 19 of 20 | 0.0% | 10 of 10 |

## The Python build

Start-up is mostly imports, and the same libraries import at very different speeds on different Python
builds. Median of seven runs of `python benchmarks/imports.py`, in environments with ksay installed:

| Python | bare interpreter | ksay's libraries |
| --- | ---: | ---: |
| 3.11.14 | 13 ms | 0.32 s |
| 3.12.4 | 21 ms | 0.41 s |
| 3.14.8 | 54 ms | 0.70 s |

3.11.14 is uv's own build, the one `uv tool install` used here, and the 3.12 and 3.14 are Homebrew's. Earlier
reports of the day ran on Python 3.14.3, which is no longer installed here, and gave `ksay` 1.5 s for the short
text, 4.7 s for the medium one and 15.9 s for the long one. A 3.14.8 imports `ksay`'s libraries 0.38 s slower than
uv's 3.11, which would account for most of the 0.5 s difference for the short text, but the 3.14.3 itself could
not be measured again. The path that writes a file did not change between those runs and this one. Whether a
difference comes from the Python version or from the build was not separated.
